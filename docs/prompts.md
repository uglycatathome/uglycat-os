# 自定义提示词（持续优化解读口径）

UglyCat OS 的筛选与解读由 6 段提示词驱动。你**不需要改代码**，只要在仓库根目录
建一个 `prompts/` 目录，放同名 markdown 文件，内容会作为「用户自定义规则」追加到
对应阶段的提示词末尾（输出格式仍由内置要求约束）。

## 可覆盖的阶段

| 文件 | 作用 | 什么时候改 |
|---|---|---|
| `prompts/dedup.md` | 跨天主题去重：什么算「同一件事」 | 觉得两条其实是同一件事，却都推了 |
| `prompts/select.md` | 精选口径：什么算大事、最多几条 | 觉得该推的没推、不该推的推了 |
| `prompts/stage0.md` | 官方特征措辞提取范围 | 想多抓某类表述（如「试点」「先行先试」） |
| `prompts/stage1.md` | 黑话解码：措辞 → 对普通人的含义 | 解读太泛、想更贴近生活 |
| `prompts/stage2.md` | 与历史公报的措辞对比 | 想强调「新提法」还是「力度变化」 |
| `prompts/stage3.md` | 一句话建议的落点 | 建议太虚、想更可执行 |
| `prompts/market_impact.md` | 利率类新闻对黄金/股市的影响 | 想补充资产配置视角 |

文件不存在时 = 完全使用默认行为，不会报错。

## 迭代方法（推荐的闭环）

1. **记录问题**：把不满意的那一期记下来，例如「今天把电影节活动推出来了」。
2. **写成规则**：在 `prompts/select.md` 里加一句可判定的规则，而不是抽象形容词：
   ```markdown
   - 标题含「电影周/电影节/艺术节」的一律不选，即使事件规模很大。
   ```
3. **重跑验证**：
   ```bash
   ./uglycat run news_digest
   ```
   看 `data/history/news_digest/<日期>/digest.md` 是否符合预期。
4. **沉淀为回归**：把这一期的不满项写成一条测试（见 `CONTRIBUTING.md`），
   避免以后又退回去。

## 写规则的几条经验

- 用**可判定的词**（「标题含 X」「同一条同时包含 Y」），不要写「要更有价值」这类空话
- 一次只改一条规则，改完立刻重跑，否则不知道是哪条生效
- 规则冲突时，内置的**硬门槛**（活动/栏目/党务/地方数据）优先，提示词只在其后生效
- 过度收紧会变成「每天都不推」，建议先用一周的真实推送观察误杀率

## 给 AI 的一句话模板

> 帮我优化 UglyCat OS 的新闻筛选口径：这一期的问题是 `<具体问题>`。
> 请按 `docs/prompts.md` 在 `prompts/select.md` 增加一条可判定的规则，
> 然后跑 `./uglycat run news_digest` 验证效果，并把这条写成回归测试。
